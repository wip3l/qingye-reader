# 阅读统计的数据约定

当前版本只提供本地统计，没有新增云端协议、上传队列或服务端合并。

## 界面与口径

- 左侧选择日、周、月、年、全部；右侧选择本机或实际存在记录的来源。只有一个来源时不显示无意义的设备下拉菜单。
- 旧版记录没有设备标识，迁移后归入“历史导入”。存在这类记录时可选择全部设备、本机、历史导入。
- 周一为一周开始；年为自然年。周/月按天、年按月、全部按年展示趋势。
- 总时长相加；阅读天数按日期去重，书籍数与排行按稳定书籍标识合并。
- 日均包含范围内没有阅读的自然日，当前周期截止今天；全部范围从最早可见记录起算。按日历日计算，避免夏令时造成 23/25 小时误差。
- 本机游客记录仍可查看，但不转移到当前登录账号。账号 A 的专属记录不会展示给账号 B 或退出后的游客。
- 书籍移出书架后显示快照书名和“本机未上架”；从未保存过名称的旧记录显示“书名未留存”。

## Schema 22

`read_stats_records` 保存阅读片段：

- `recordId`：结算时生成的唯一身份，失败重试必须沿用。插入使用 `INSERT OR IGNORE`，不重复累计。
- `ownerId`：片段发生时的账号，空串表示游客/旧版历史。
- `deviceId/deviceName`：来源安装的身份与名称；身份复用账号同步已有的 `account_cloud_sync_state/device_id`，名称不作为主键。
- `bookKey/bookUrl`：跨设备稳定身份与本机地址。使用 `BookIdentity.cloudIdentityValue`，本地文件可使用已有内容指纹；不会仅凭同名合并不同书籍。
- `dayKey/durationMs/startedAt/lastReadAt/timezoneOffset`：发生日、时长、起止时间与当地时区偏移。历史汇总没有准确起点，`startedAt=0`，不得解释为实际会话。
- `deletedAt`：删除标记，默认 0。删除不移除身份，重试同一记录不会复活；未来同步需传递删除标记。
- `legacyKey`：旧表日期和地址组成的导入键，唯一约束确保迁移重复运行不重计。

`read_stats_books` 独立保存书名、作者、封面、稳定书籍身份和隐私标记。结算及删除书籍前更新快照。隐私切换同步更新快照；查询优先采用现存书籍隐私状态，书籍不存在时采用快照。

旧 `read_stats` 保留用于升级恢复，但新统计不再读写它。迁移是可重试的；全部步骤成功后才把 schema 标记为 22。

## 后续同步必须遵守

1. 保留原始记录 ID、账号和来源设备，下载的记录不能重新归成本机增量。跨设备同时阅读仍按设备时长求和。
2. 游客历史归属、旧备份的重复导入及设备重装需要专门的导入策略，不能自动上传到每个登录过的账号。
3. 页面删除按书籍身份、周期、设备和可见账号范围执行；不能把本机没有的云端记录视为删除。所有设备删除如何覆盖尚未上传的离线片段，需要同步协议另行定义。
4. 私密记录当前只在本机保存；接入同步前必须确定隐私同步策略，不能复用普通书籍的上传分支。
5. 当前快照中的封面地址可能是本地路径，未来上传需处理可移植资源，不能直接让另一台设备使用原设备沙箱地址。
6. 解绑设备应保留历史来源；设备列表不能只取仍在线或仍授权的设备。

## 验证

`node --test scripts/reading-stats-check.mjs` 运行生产统计计算、计时器及实际 SQLite 迁移/筛选/删除 SQL，覆盖多设备去重、跨年/闰年/夏令时、迁移重入、账号隔离、删除留名、隐私与重试。
