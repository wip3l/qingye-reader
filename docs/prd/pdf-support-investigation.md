# PDF 格式支持调研与实施方案

日期：2026-11-01。状态：用户已确认并进入实施；代码和验证结果见 `docs/pdf-support-validation.md`。

## 1. 目标与推荐结论

沿用现有 TXT / EPUB / MOBI 的本地书籍管理体系，为 PDF 增加应用内原版式阅读能力。推荐采用 HarmonyOS 原生 `@kit.PDFKit`，以独立 PDF 阅读页承载文档，复用导入、书架、封面、原文件导出、阅读时长和已有同步能力。

PDF 的固定页码与文字书的动态分页含义不同。PDF 保留原文件、页面和目录，不经过 EPUB HTML 转换器，不生成全书图片，也不进入文字分页器。

本轮的确认对象为本文完整实施范围。用户同意后按第 11 节依次实施；原生能力验证失败、需要替换阅读内核或改变范围时再提交调整方案。

## 2. 现有实现与可复用项

| 现有模块 | 调研结果 | PDF 接入方式 |
| --- | --- | --- |
| `entry/src/main/ets/core/book/LocalBookService.ets` | 统一管理文件选择、沙箱副本、格式、内容哈希、解析版本、数据库索引、导出和删除；当前支持 txt/epub/mobi | 增加 pdf 格式和独立导入分支，复用原文件管理 |
| TXT 导入 | 分块读取、编码识别、章节识别、分批写入正文 | 参考分块哈希、分批写入和大文件响应策略；PDF 不使用 TXT 切章 |
| EPUB 导入 | 解压并解析 OPF、目录和 spine，经 `EpubChapterPlanner` / `EpubHtmlConverter` 生成章节正文与图片标记 | 复用元数据优先级、目录展示经验及解析版本机制 |
| MOBI 导入 | `MobiImportTask` 在 TaskPool 中拆书，生成 HTML 后复用 EPUB 分章流程 | 参考耗时工作移出主线程的组织方式；不将 PDF 转成 MOBI/EPUB |
| `ReadBookEngine.ts` / `LocalChapterContentLoader.ts` | 阅读内容契约为章节字符串，本地恢复加载器仅处理现有 type=2 的资源 | 为 PDF 增加格式保护，避免误入正文加载、预加载和文字缓存流程 |
| `pages/ReadBook.ets` | 多个入口统一进入该页；已有跳转 `AudioBook` 的分流；进入时会预热文字引擎、注册进度及初始化 TTS | 参考有声书分流方式，但 PDF 识别须早于文字阅读初始化 |
| `ReaderProgressCheckpoint.ets` | 将后台、锁屏等生命周期保存动作交给当前阅读页，并控制写入归属 | PDF 注册自己的页码保存动作 |
| `ReadStatsTracker.ts` | 按书籍 URL 和页面可见性统计阅读时长 | PDF 阅读页复用 |
| `BookIdentity.ts` / `CloudSyncCoordinator.ets` | 同一本本地文件通过内容哈希匹配，现有进度协议包含 chapterIndex/chapterPos | 用稳定的物理页索引复用进度协议 |
| WebDAV / OPDS / 云文件 / 备份 | 下载后最终进入 `LocalBookService`，但多处仍有独立格式判断和格式推断 | 同步补齐全部格式入口、备份恢复和文件导出 |

相关历史提交：

- `12c2e2de`：导入未加密 MOBI6，并复用既有目录、封面和插图处理流程。
- `51cbc60d`：大型 EPUB 按锚点切章、预读和主线程让出优化。
- `49311b17`：大 MOBI 导入移入后台，修复主线程长时间占用导致的进程终止。

这些历史问题决定了 PDF 实施时必须先验证后台索引和大文件行为，不能将同步 PDF 解析直接搬入 UI 线程。

实施校准：测试设备上 `PdfController.searchKey()` 在回调过程中触发原生崩溃，故正式实现使用独立后台 `PdfDocument` 搜索并用 `setHighlightRects()` 呈现命中。API 21 及以上使用文档搜索，API 20 用已有文本对象及字符矩形搜索；不再调用视图搜索接口。原生阅读内核及用户确认的搜索功能保持一致。

| 候选方案 | 取舍 |
| --- | --- |
| 原生 PDF Kit + 独立阅读页（推荐） | 能保留固定版式，直接使用平台缩放、搜索和页面事件；在当前 SDK 内可接入 |
| 抽取文字后进入现有阅读器 | 可复用字体和 TTS，但阅读顺序、表格、多栏和扫描页需要额外处理，无法覆盖原版式阅读目标；留作后续文字重排功能 |
| PDF.js / 额外原生渲染库 | 会引入新的资源、依赖和维护工作；首版先使用平台现有能力，原生验证失败时重新评估 |

后续范围：打开密码输入及安全保存、OCR、文字重排、TTS、基于全文的 AI 阅读、PDF 编辑/批注写回、PDF 自定义书签、PDF 页内精确坐标跨设备恢复，以及局域网浏览器 PDF 阅读。

## 5. 导入与数据设计

1. 扩展 `SUPPORTED_FORMATS`、格式提示、文件选择后缀；系统文件关联增加 PDF MIME/UTD，最终值以本机声明核对为准。
2. 增加本地 `TYPE_PDF`（拟用当前未占用的 4，实施前再次核对），保留 TXT=1、EPUB/MOBI=2；以 `localFormat=pdf` 识别具体格式，不能把 PDF 当成漫画。
3. 在现有 `local_books` 管理范围内保存原文件和派生文件；原文件继续分块计算 `localContentHash`。
4. 新增 `PdfImportTask`，后台任务内部创建、读取和释放 `PdfDocument`，返回可序列化的元数据/索引；不在线程间传递原生文档对象。同步打开和封面渲染不得阻塞 UI；后台方式验证失败时先调整实现，不能直接回退到主线程解析大书。
5. 解析总页数、书名、作者和内嵌目录。优先级为用户自定义信息、有效 PDF 元数据、文件名；目录错误或无元数据可降级，文档无法打开则失败。
6. 生成一张限制尺寸的封面，建议长边不超过 600px；释放临时 PixelMap、编码器和文档。封面生成失败不阻塞可正常阅读的 PDF 入库。
7. 使用“物理页”生成轻量 `BookChapter` 索引，`index` 为 0 起始页索引，标题为“第 N 页”，URL 为书籍地址附加 `#page=N`；不写空白正文或整页位图到章节正文缓存。分页索引分批入库，PDF 内嵌目录另存为带层级的派生索引文件。
8. 为 PDF 单独管理解析版本。派生索引丢失时从原文件重建；原始 PDF 不应被普通阅读缓存清理误删。
9. PDF 导入采用暂存、校验、提交方式：成功后再替换书籍记录及旧资源；文件切换与数据库提交之间保留可恢复的旧版本。失败清理暂存，重复导入失败不得损坏原有副本、封面、分组和阅读位置。
10. 本地批量导入继续允许部分成功，并展示失败文件及原因，至少能区分密码、损坏/不支持与文件读取失败。

建议新增模块：`core/book/pdf/PdfModels.ts`、`PdfBookService.ets`、`core/concurrency/PdfImportTask.ets`。平台 PDF 对象留在 entry，不向通用 sourceengine 增加 PDF Kit 依赖。

## 6. 阅读入口与页面

新增 `pages/PdfReadBook.ets`、`components/reader/PdfReaderView.ets`，并在 `main_pages.json` 注册路由。

所有既有入口最终应能进入 PDF 阅读页，包括书架、系统打开、WebDAV/OPDS 下载后打开、云占位书下载、最近阅读快捷方式和卡片。

在 `ReadBook` 入口增加尽早的格式分流保护，采用 `replaceUrl`，保留 bookUrl 和快捷方式返回语义。PDF 分流必须发生在文字引擎预热、文字进度注册、TTS 初始化之前；异步识别期间的 `onPageShow/onPageHide` 等生命周期也要门控，不能先写入文字页进度再跳转。PDF 页自行调用现有云下载/WebDAV 缓存能力准备原文件。

PDF 页顶部使用既有主题和语义色展示返回、书名、目录、搜索及阅读设置；底部展示“第 N / M 页”、前后页和跳转。正文区域由 PdfView 接管缩放与滚动，外层不叠加文字阅读器的全屏翻页手势。目录、搜索、页码输入等弹层打开时，避免正文误触。

复用现有页面安全区、系统栏和基础返回交互。PDF 工具栏仅展示适用功能，字体、行距、文字替换、文字翻页动画、听书及漫画着色、翻译不出现在 PDF 设置中。端侧 AI 超分按第 13 节的追加授权接入。首版优先使用项目已有页面转场，封面翻书动画的适配不能成为文字阅读器的大范围重构。

## 7. 页码、进度与同步约定

- PDF 物理页索引稳定为 `0..pageCount-1`；用户看到的是 `1..pageCount`。印刷页码、罗马数字页标签和目录条目数量不作为进度索引。
- `totalChapterNum=pageCount`、`durChapterIndex=当前物理页索引`、`durChapterPos=0`、`durChapterTitle=第 N 页`；仅 PDF 解释为页码，其余格式继续使用原语义。
- 显示进度采用 `(pageIndex+1)/pageCount`；首页也需尊重未读/已开始阅读的区别。应用内统一通过 PDF 进度辅助函数计算，避免书架和阅读页各算一套。
- 目录条目映射到物理页，不把目录条目写成进度章节；无目录、重复目录目标或更换横竖屏都不会改变物理页索引。
- 本机恢复和跨设备同步均以“页”为首版精度；缩放、单/双页、连续浏览等视图偏好独立保存，不把像素偏移塞进现有文字字符位置字段。
- 只有文档成功打开、目标页恢复完成后才允许新的页码保存。页码事件节流写入；离开、锁屏或进入后台时通过 `ReaderProgressCheckpoint` 刷新最后稳定位置。
- 复用现有内容哈希匹配、时间戳冲突处理和阅读进度协议。不同 PDF 文件不按书名套用页码；文件更新后校验并限制页码范围。
- 补齐书架、详情、本地管理和目录入口的“页/章”显示分支，避免出现“第 12 章”或把目录数当总页数。沿用现有书架内容分类，增加 PDF 格式标识，首版不新增云端媒体分类。

首版不承诺 PDF 自定义书签同步。现有本地书签同步也并非通用开放能力，不应直接套用网络书籍书签流程后对用户承诺跨设备可用。

## 9. 性能、异常与生命周期

- 应用层不预渲染全书，不抽取全书正文，不为扫描 PDF 生成整书图像副本；首版额外持久化仅限封面和轻量目录/索引。
- 元数据和目录解析按文档串行限制并发；目录遍历限制深度/节点数，异常目录降级为页导航。封面按指定分辨率渲染，避免先生成超大位图再缩小。
- 以会话标识防止“打开 A 后快速打开 B”时旧异步任务覆盖新页面；离开后作废搜索、加载和目录回调。
- 切换文档前、页面销毁时调用 `releaseDocument()`；重复加载遵循 SDK 先释放再加载的约束。
- 缺文件提供重新下载或重新导入入口；损坏、密码、解析错误分别提示。导入失败、打开失败和取消操作不写虚假新进度。
- 运行时检查 `SystemCapability.OfficeService.PDFService.Core`；能力不可用时明确提示，不进入文字解析流程。
- 原生渲染内存和缩放行为需要设备实测；不以接口存在推断大文件必然流畅。

| 旧格式 | TXT 编码/切章、EPUB 目录/插图/混排、MOBI6 导入及不支持提示、小说/漫画/听书入口、原有同步与原文件导出 |

自动检查重点放在页码换算与边界、目录映射、进度保存门控、失败回滚、格式识别和同步往返。参考项目现有 `scripts/*-check.mjs` 风格新增 PDF 检查；复用 EPUB/MOBI、阅读进度、云传输和备份相关回归。原生解析、缩放、字体渲染、资源释放及锁屏恢复必须在设备验证，不能用 mock 成功替代。

构建执行与变更相关的 ArkTS 静态检查及 Hvigor 编译。仅方案阶段不执行构建或修改运行环境。

## 13. AI 超分追加范围

用户已明确要求“接入”，沿用本聊天确认的方案实施，无需重新确认。

- PDF 设置增加独立 AI 超分开关，默认关闭，按书籍变量 `pdfSuperResolution` 保存；关闭不改写 PDF 原文件。沿用漫画超分的 API 26、设备能力、账号会员／试用及运行时失效判断。
- 保留原生 PdfView。后台为符合条件的扫描页面生成受限尺寸图片，复用 ReaderComicSuperResolution 与全局队列；结果使用 API 26 原生坐标转换贴合原页面。原生内核继续负责翻页、缩放、单双页、连续滚动及物理页进度。
- 首版保守筛选无文字／矢量对象、图像覆盖主要页幅、未旋转且页面裁切原点一致的扫描页。文字、混合、复杂裁切或旋转页继续原生显示；高分辨率扫描页不为凑超分条件主动降采样。后续可扩展图像对象级增强。
- 光栅输入宽度不超过 1024、总像素不超过 1 Mi；只处理当前及相邻两页，最多保留三页文件引用，页面源图与结果一起纳入漫画图片缓存预算。
- 轻点唤出菜单后可点“查看原页／查看超分”即时对比。搜索、触摸、滚动、缩放和离开页面时暂停覆盖，停稳后重新定位；AI 失败或权限失效继续显示原页。
- 验证覆盖后台分类／光栅、真实系统推理与结果缓存、原页对比、原生跳页缩放，以及翻页／退出期间的异步取消和缓存引用释放。不将小样本验证描述为所有扫描文档均可改善。
