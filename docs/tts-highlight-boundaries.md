# TTS 句末高亮边界优化

## 问题与目标

原分句在句号、问号等标点后立即结束，可能把紧跟的右引号留到下一片段。
例如 `我不要。”\n云果儿……有我没？”` 会出现上一段右引号随当前段高亮、当前段右引号留到下一段的现象。
系统与云端请求分段已有的右引号收取逻辑还受长度上限限制，在上限处也可能拆开句尾。

## 实施方案

1. 在 `SystemTtsReader` 中集中处理片段边界，把连续句末标点和闭合引号、括号归入前一片段。
   长度目标允许为完整句尾稍作延长，但不能越过所属文本范围、空白或下一句的中文开引号。
   数字小数点不当作句末标点；英文直引号区分开闭，单词中的撇号和转义引号不当作闭引号。
2. 自定义 TTS、系统 TTS、云端请求和云端兜底高亮复用这个规则。
   分页再次切分时也修正边界，防止把已收齐的标点重新拆开。
3. 云端时间轴映射到原文后，对起点和终点使用相同规则，让相邻高亮衔接。
   纯标点时间片被前一片段吸收后可以为空；保留后续正文的播放时间戳。
   在客户端兼容已有服务端时间轴，本次无需部署服务端。
4. 面板继续按原文范围展示，不通过删引号、补换行或整体平移高亮掩盖边界问题。

## 验证

- `node scripts/reader-tts-boundary-check.mjs`：截图文本、各分段长度边界、连续标点、省略号、嵌套括号、分页、英文引号、小数、UTF-16 原文映射和云端播放回调。
- `node scripts/reader-tts-panel-text-check.mjs`：修正前后输入范围均保持展示文本完整，且长段落跟随逻辑正常。
- `node scripts/reader-tts-error-recovery-check.mjs`：音色切换、重试、过期回调及清理回归。
- DevEco Hvigor `assembleHap`：验证 ArkTS 编译和应用打包。

设备验收时，分别选择系统、自定义和云端音色，检查 `。”`、`？！”`、`……」` 的整体高亮，以及翻页和暂停恢复后的边界。
