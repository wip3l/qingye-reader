# 原生书源能力补充实施清单

整理日期：2026-10-26。依据：外部《ISSUE-全部缺失能力.md》的 16 项建议，以及当前工作区代码核对。

本文记录本轮实施状态；代码与 Node 验证已落地，API 26 真机网络回显、响应头、条件重试、WebView 与媒体同/跨 origin 302 已验证。媒体实测发现的问题已修复并复测，600 / 1000 / 3000 章完整目录基线已记录；完整设备矩阵尚未完成，详见 [实施与验证记录](native-source-capability-followup-validation.md)。此前已完成的网络兼容、并发预算和内联评论见 [已有实施计划](source-capability-implementation-plan.md)，本清单接续其成果。

## 1. 范围与结论

- 第一批：响应头透出、请求诊断、聚合失败处理、条件重试与退避、文档修正。
- 第二批：脚本耗时诊断、媒体自定义请求头。
- 先验证再决定：自定义请求头丢失、提高计算预算、统一浏览器自动回退、结构化 DOM 接口、搜索/发现阶段保存书籍变量。
- 已有能力不重复开发：默认 UA、按钮 baseUrl/source.url、详情 keep 跨阶段传值、WebView 请求与 browser.render。
- 外部文档对应轻页 4.4.933；当前工作区行为不能直接证明该已发布版本的行为。复现需记录应用版本、提交和设备信息。
- 截至整理时，原生脚本 Node 回归 106 项断言通过。该结果不等于真机 SDK、QuickJS 性能或第三方站点验证通过。

## 2. 第一批：网络结果与失败处理

### A. 透出响应头（P1，对应原第 4 项）

- [x] 在 NativeResponse、服务适配层、脚本宿主及后台桥接中传递响应头，脚本结果增加 headers。
- [x] 约定小写键名，明确多值头的表示和合并规则；Cookie 继续由现有机制管理。
- [x] 区分原生 HTTP 与 WebView 的可观测范围：拿不到的头不得伪造，用明确的可用性标记区分“未取得”和“确实没有”。
- [x] 保持 ok/status/body/url/finalUrl/error 与 json() 的既有语义；包含 4xx/5xx 的失败响应也应透出可观测的头。
- [x] 更新接口文档，给出读取 content-type、retry-after 的示例。

验收：200、429、503、重定向、网络异常和 WebView 路径均有覆盖；验证大小写、多值头和工作线程往返。只返回与最终响应对应的头，不混入中间重定向响应。

主要入口：NativeSourceRunner.ts、NativeSourceService.ts、NativeScriptHost.ts、NativeJsPrelude.ts，以及现有 HTTP/WebView 响应模型。

### B. 完善请求诊断（P1，对应原第 8、12、14 项）

- [x] 扩展现有调试页执行明细，统一展示方法、地址、传输通道、状态、耗时、错误、重试次数与原因。
- [x] 展示可观测的请求头和响应头；将“传给 SDK 的请求头”与“服务端实际收到的头”明确区分，前者不能标为抓包结果。
- [x] 区分正文字符数、可计算的编码字节数和实际传输字节数；未知的网络字节数不以 body.length 代替。
- [x] 为失败请求生成一致的摘要，可由阶段错误引用；多个请求用关联标识定位，避免只剩脚本行号。
- [x] 日志和导出继续脱敏 Cookie、Authorization、Token 等凭据；不记录完整请求体或响应体作为默认诊断内容。

验收：单请求、批量请求和重试能够对应到各自记录；已知 403 只标为 HTTP 403，不能仅凭状态码或响应长度判定 WAF；脱敏后仍能定位失败项。

主要入口：NativeScriptHost.fetch、AnalyzeUrl/HttpClient 请求链路、现有书源调试记录与报告导出。

### C. 聚合失败汇总与严格模式（P1，对应原第 3 项）

- [x] 保留 http.all 默认按输入顺序返回逐项结果的兼容行为，不把所有部分失败改成自动抛错。
- [x] 增加可选严格模式，暂定 http.all(list, { failOnPartial: true })；该名称为拟定接口，实施时同步校验、桥接与文档。
- [x] 严格模式在批次收集完成后发现失败则抛出批次错误，包含成功数、失败数及从 0 开始的失败索引；失败摘要可关联请求诊断。
- [x] 取消、超预算和参数错误保留独立语义，不伪装成普通 HTTP 部分失败；中断情况下不得声称整批已经完成。
- [x] 修正文档中只用 if (r.ok) 跳过失败页的聚合示例，提供“允许部分结果”与“要求完整结果”两种写法。

验收：三项请求中第二项失败、全部失败、空批次、完成顺序不同、取消及预算耗尽；默认行为不变，严格模式不把不完整目录或结果当作完整成功。

说明：当前每项已有 ok/status/url/error，可按索引识别失败；暂不增加功能重叠的 http.allSettled。

### D. 条件重试与退避（P1，对应原第 5 项；依赖 A、B）

- [x] 保留 retry 数字形式的兼容语义；增加对象形式，拟包含 times、onStatus、backoff、base、maxDelay，并严格校验。
- [x] 明确 times 为初次请求之外的重试次数；支持固定/指数退避，可加入抖动，次数和间隔均有上限。
- [x] 支持按配置读取 Retry-After，包括秒数与日期形式；等待必须受单请求剩余时间及脚本总预算约束。
- [x] 提供保守示例：对 429/503 退避，不默认对 403 密集重试。
- [x] 明确 POST 等非幂等请求的重放条件，不随对象式默认策略自动重复有副作用的操作。
- [x] 在一个层次管理策略，避免与已有超时重试、HTTP/1.1 降级、WebView 传输回退叠加成不可控请求次数；明确实际尝试的计数与总上限。
- [x] 等待期间支持取消，重试不重置总预算；首批不增加重试时执行脚本或动态换头的回调。

验收：429 后成功、503 连续失败、403 不匹配、Retry-After 无效或超预算、退避期间取消、非幂等方法，以及多个既有回退机制同时命中的尝试次数。

主要入口：NativeSourceSpec/NativeSourceRunner、NativeScriptHost、NativeSourceService、AnalyzeUrl，必要时调整共享请求策略。

### E. 文档与接口边界（P2，可与上述功能同步；对应原第 2、6、7、9、11、13、16 项）

- [x] 分别说明声明式 webView、http 请求 webView、browser.render 和 browser.verify；注明前两类超时单位中秒与毫秒的差异。
- [x] 明确搜索/发现可使用页面加载和渲染能力，但 browser.verify 走“去验证”提示；页面渲染成功不保证交互式验证通过。
- [x] 记录已有默认 UA、按钮 ctx.baseUrl/ctx.source.url、详情 keep → ctx.book.vars 的示例。
- [x] 列出表达式与脚本的调用方式：内置函数通过 native.名称() 调用；先完善示例，不默认注入大量同名全局 stub。
- [x] 统一 vars.options/default 的类型说明、导入校验和设置页行为；当前运行器会将静态选项转成字符串，不能仅凭这一层承诺所有入口已支持数字。
- [x] 补充 native.selAll 提取 @html 后继续选择字段的示例，避免把现有能力误写成“只能用正则”。

验收：公开示例可在相应环境运行；数字选项覆盖导入、默认值、设置页选择与保存重载。示例使用虚构数据或受控测试服务。

## 3. 第二批：性能诊断与媒体请求

### F. 脚本耗时诊断（P2，对应原第 10 项）

- [x] 利用现有 QuickJS 结果中的 cpuMs 补充阶段耗时和超时错误，区分脚本计算、宿主等待与总耗时。
- [x] 复制/导出报告前置阶段性能摘要；调试页新增显式 3000 章检查开关，并显示实际章节数和检查上限，默认仍取前 32 章。
- [x] 使用固定 JSON 样本验证 600、1000、3000 章完整目录，记录设备、系统、引擎基线、3000 章重启后首轮/热运行，以及各档 6 轮局部解析分布。完整阶段样本量有限，不宣称完成多设备或复杂 HTML 性能矩阵。
- [x] 先保留 2 秒计算预算；只有真机证据显示合理脚本仍受限时，再评估限额调整或可配置方案。

验收：正常完成与超时都能看到可用的耗时指标；不得用 Node 测速乘以假设倍率代替 QuickJS 实测。

### G. 媒体自定义请求头（P2，对应原第 15 项）

- [x] 梳理 mediaHeaders 从规则求值到漫画图片、音频请求的实际过滤位置，明确与封面、插图和视频的适用范围。
- [x] 以受控测试服务需要的 X-Media-Token 等合法自定义头验证扩展方案，避免仅修改入口、下游仍丢头。
- [x] 同步检查重定向、跨域凭据、缓存身份和日志脱敏，不以无条件删除所有过滤替代契约设计。

验收：自定义头到达测试服务，旧白名单行为兼容，缓存不会因不同授权头混用结果，跨域重定向按明确规则处理。

API 26 真机发现 NETWORK_CONNECT 不足以保护 SDK 内部跳转，已改为 REDIRECTION 截停自动跳转、应用逐跳发送；同时修复空 302 响应体处理。用户确认两张测试图均显示，服务端确认同 origin 保留测试头、跨 origin 移除。其他系统版本和音频跳转仍单独验收。

## 4. 先验证、后决定的项目

| 项目 | 当前判断 | 进入开发的条件 |
| --- | --- | --- |
| 自定义请求头丢失（原 1） | 当前有透传链路；相同 403/正文长度不能证明未发送 | 用真机访问受控回显服务，分别测脚本、声明式、原生 HTTP、WebView 和重定向，确认具体丢失层后修复 |
| 统一浏览器自动回退（原 2） | 已有 WebView、render 和特定传输错误回退，尚无统一挑战页回退契约 | 先验证现有接口不能满足的场景，再定义触发条件、最多一次回退、取消、预算、Cookie 与最终响应语义；仍保留交互验证入口 |
| 增加会话存储或扩展 keep（原 9） | 详情到目录/正文已有 keep；搜索/发现保存每本书的数据是新需求 | 提供现有机制无法满足的场景，明确书籍身份、并发、生命周期、过期及重载后行为 |
| 计算预算改为 5 秒（原 10） | 缺真机性能证据 | 完成 F 后按结果决定，不能照估算直接提升 |
| 结构化 DOM 接口（原 16） | 已有字符串选择器，节点对象是新接口 | 用复杂页面样本证明重复解析有明显成本，再比较批量字段提取与节点句柄方案的收益、内存和生命周期 |

自定义头问题若复现为广泛功能阻断，可提升优先级；在证据出现前不预设为 P0。
