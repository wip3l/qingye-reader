# 有声书与 TTS 音频打断

有声书、PCM TTS（系统合成及返回 PCM 的自定义声音）、文件 TTS 均监听播放器的 `audioInterrupt`。

- `PAUSE`：强制打断由系统暂停；共享打断由应用主动暂停。PCM 暂停推进播放时间轴和消费待播放数据。
- `RESUME`：仅恢复此次临时打断的播放，并等待异步暂停完成。用户手动暂停、停止、换播放器或新的打断会使旧恢复请求失效。
- `STOP`：永久失去焦点，取消自动恢复资格。共享通知主动暂停；强制通知由系统停止。由用户操作恢复，不轮询抢占焦点。文件 TTS 被系统强制停止时仍走现有朗读中断错误恢复流程。
- `DUCK` / `UNDUCK`：保留既有音量策略，不把提示音一律改成暂停。

上述规则处理系统实际下发的通知，不通过前后台切换判断通话是否结束。系统 TTS 的 `playType=1` 引擎直播放音降级路径由系统语音引擎管理，不经过这三个播放器。

## 回归检查

运行 `node scripts/audio-interruption-check.mjs`，使用真实播放器源码及平台替身验证强制/共享暂停、恢复、永久停止、手动控制优先、过期通知、异步竞争和 PCM 数据保留。

真机需分别验证有声书、系统 TTS、自定义 PCM TTS、自定义文件 TTS：

1. 播放中接入/挂断电话、微信语音通话，检查打断与续播；同时测试未接通、拒接。
2. 微信语音消息播放及录音单独测试，记录实际收到的 hint/force，不能假设与语音通话相同。
3. 打断期间手动暂停或停止，结束后不得自行发声；随后应能由用户继续播放。
4. 快速接入/结束、连续打断，检查是否漏读、意外续播或停留在暂停状态。
5. 单独锁屏、解锁及后台持续播放，确保不会因前后台生命周期误触发暂停；若设备下发共享 PAUSE，按音频通知暂停并等待 RESUME。
6. 长时间通话后检查阅读进度；通话等待时间不得计入 PCM 播放进度。

自动化测试不证明电话或某个微信版本必然下发 PAUSE/RESUME，实际设备行为需以上真机测试确认。
