# 功能／逻辑 Bug 记录

## BUG-1 PDF 光栅页面裁切与坐标边界

**日期**：2026-11-01。
**模块**：PDF 后台光栅与 AI 超分覆盖。
**现象**：扫描样本被误判为不支持；分类修正后，第一次截图发现增强图只有左上角内容被放大。
**根因**：未定义 CropBox 时，测试设备返回四个零，而非 MediaBox；另外 getAreaPixelMap 的 PdfMatrix 宽高需要使用输出光栅尺寸，沿用页面点数会使小尺寸画布裁切内容。
**修复**：空 CropBox 回退 MediaBox；保留原生页面矩形顺序用于视图坐标转换，分类只归一化边界比较；光栅矩阵与输出尺寸保持一致，升级源图缓存版本。
**验证**：真实设备测试在光栅图右上、左下采样绿色／蓝色象限，避免只检查尺寸或推理返回值；原页与增强图截图边界一致；Node 测试覆盖缺失 CropBox、矩阵尺寸、原子写盘及资源释放。
**状态**：已修复。

## BUG-2 PDF 增强图片的命中区域阻断原生拖动

**日期**：2026-11-01。
**模块**：PDF 超分图层与阅读浮层。
**现象**：增强图片覆盖区域无法拖动，右侧未覆盖的原生滚动条仍可拖动；原页对比按钮加 Block 后无法点击。
**根因**：HitTestMode.None 只让节点自身不响应，子 Image 仍可命中并挡住下层 PdfView；HitTestMode.Block 会屏蔽自身的子节点，不能用于带按钮的面板。
**修复**：增强图层根节点使用 BLOCK_DESCENDANTS，让整棵图片子树退出命中；阅读浮层使用 BLOCK_HIERARCHY，保留内部按钮响应并阻止下层 PDF 同时收到触摸。正文点按改为容器观察触点及位移，不添加竞争手势。
**参考**：本机 SDK `openharmony/ets/component/enums.d.ts` 的 HitTestMode 定义（两种模式均从 API 20 提供）。
**状态**：实现已修正，最终真机手势回归记录见 PDF 验证文档。
